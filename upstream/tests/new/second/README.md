# Second verifiers of the toy files, in Python

The C++ programs in `blocks/` have a prover and a verifier from one set of headers. The programs here are verifiers written a second time, in plain Python (the standard library and `docs/format/format_rules.py` only). They call no code of `blocks/`. They were written from the texts in `docs/format/toys/`, not word for word as these pages stand, with written answers of these texts' writers to questions, and from the format's page. How far each is independent of the C++ sources its head says; the least independent is `proof_check.py`: it is not independent of the C++ sources of what it checks, and its block on claims that leave a link follows the C++ headers' own comments and lines. They are slow and small on purpose: they are meant to be read beside the texts. They know one field (Goldilocks). The toy's tables have a record (the stored answers to samples of a weight table's rows), and the code here reads it in the key files, leaf files and proofs that `run_honest.sh` makes.

| file | what |
|---|---|
| `run_honest.sh` | one command: builds the three tools, makes the honest toy files, their altered copies and two entries made false out of an honest entry's own bytes (the scripts call them «bent»), and has each judged by the C++ verifiers and by these programs; it builds no cheating program; its head says what lands where |
| `toy_check.py` | the toy «product»; also the field, the channel and the report that the others use |
| `links_check.py` | the toy «links» |
| `key_check.py`, `lin_check.py`, `zkpy.py` | a key file: the look-ups and ranges, the batching of pending rows, the test on the committed table; the blocks' common ground |
| `entry_check.py` | an entry file |
| `files_check.py` | calls the last two on the toy «key and entry»; makes altered copies and the two false entries made out of an honest entry's bytes; no formula of its own |
| `proof_check.py` | a PROOF file of a toy batch (head, first chain, place, shared chain, second chain): toy links whose claims on the committed matrix leave the link; three requests in a binding tree of depth 2; once with three links, once with ONE link (one row on the table: nothing is batched behind the last test) and a layout that holds arrays, once with two further oracle messages in the second link (one in a leaf class, so a tree, of its own; one at a later moment). It lists every opening with its tree and its place in the file. Its «accepted» means «under the given parameters»: the plans, codes and shapes that the C++ verifier derives from the two public files are taken from files that the tool wrote. It is less independent than its sisters: it is not independent of the C++ sources of the frame, which its head lists. The number in a proof's head: it requires 0 with a root out of a key and a number above 0 with a root out of an entry, as the tool does that makes its files; that is not the format's rule R14.2. The three programs number stored copies from 0 and read them against an entry's root: by that rule this program would refuse a proof of theirs on copy 0 (by reading: it reads toy links alone and has never been given a program's proof). The format's page tells the programs' numbering; this program and the tool do not follow it |
| `vertex_values_test.py` | a test of these verifiers themselves on «one value at a vertex», which no file can exercise |
| `vectors_against_the_toy_files.py` | not a verifier: compares the parameters that `blocks/frame/handover_files` writes for the toy «key and entry» with the known answers in `docs/format/format-vectors.txt`: two items of the key file's one-time chain and one of the leaf file, and, for each of the key file's three chains, the number of rounds, their names in order, and for each round the message's bytes, the elements sampled and how many are not 0, where the rules give a number |
| `expected/bent.tsv` | the two false entries that `run_honest.sh` makes out of an honest entry's bytes: how each is made, and at which check each must fall |
| `expected/sha256.txt` | the bytes that the tools must make |

```
D=$(mktemp -d) && bash tests/new/second/run_honest.sh "$D/work" 4
```

The last number is how many build jobs run at once (4 if you leave it out). At one job it takes about eight minutes and under 1 GB of memory in any one process, and ends with «ALL AS EXPECTED» and counts. It deletes nothing (the folder that mktemp -d made stays until you remove it), and it makes the work folder itself: it stops if the folder exists, if the folder that is to hold it does not exist, or if another account could write above it.

Twelve false proofs and files are stored, with four honest controls, in `examples/protocol-toy-false-files/`: its `LIST.tsv` gives each file's checker and the words that it must print, and its `stored_false_test.py` gives each file to its checker. Eleven of the twelve were made by cheating builds of the library's tools; neither the cheating code nor the script that built those and made the files is part of this repository, so a reader cannot make any of the eleven again. The twelfth, BENT_SWAP, is one of the two bent entries, which `run_honest.sh` makes again with the same bytes. Nothing inside a false file marks it as false: only its place in `false/`, the word «cheat» in its name and its line in `LIST.tsv` do. A verifier that accepts one is broken. One of them, SEAM_OTHER_MATRIX (`false/proofs/0.cheat-SEAM_OTHER_MATRIX.proof`), is a proof out of a batch that is false as a whole (it is proved on another matrix's stored table under the honest copy's name): it has no honest neighbour.

Nothing is hidden in any of these files: witnesses and coins come from small public numbers.

If you change one of these programs to see that it notices a fault, run your changed copy from a folder of its own: a program takes its sister files from its own folder, and only `format_rules.py` from the folder that you name first.
